### Exact steps
1. **Buy + attach the domain first** (item #10 above): quickfilesconverter.com → Vercel project `allfilesconverter` (add domain in Vercel dashboard → project Settings → Domains; set DNS at the registrar). Verify the site serves on the custom domain.
2. **Update `SITE_URL`** in `src/lib/site.ts` (currently `'https://allinoneconverter.vercel.app'`) to the custom domain. The sitemap, canonical URLs and llms.txt regenerate at build (prebuild script already does this).
3. **Commit + push, then deploy via gitSource only** (create_deployment, target production; NEVER pass teamId — 403; NEVER pass projectSettings override; MCP file-upload fails >~96KB). Verify live with curl (status + content markers) before telling him.
4. **Then rename the GitHub repo**: kingsaqib25-code/allfilesconverter → quickfilesconverter (repo Settings → General → Repository name). GitHub keeps redirects for the old repo URL, and Vercel's git integration follows the rename — deployments continue. Update the local clone's remote (`git remote set-url origin …`).
5. **Then rename the Vercel project**: dashboard → project Settings → General → Project Name → quickfilesconverter (project id prj_3oXt7gznACuu5l8VWDwoSsNoKqnH stays the same).

### Risk (the reason for the order)
Renaming the Vercel project changes the live `.vercel.app` URL from `allinoneconverter.vercel.app` to `quickfilesconverter.vercel.app`. **The old URL stops serving the site** — every existing link, bookmark and Google-indexed URL pointing at allinoneconverter.vercel.app breaks, and the released old name can be claimed by someone else. That is why the custom domain must be live and canonical FIRST: once the domain is the address people use, the `.vercel.app` URL is only a fallback and the rename is safe. Never rename before the custom domain is live. The repo rename alone is low-risk (GitHub redirects); the Vercel rename is the breaking one.
